# 数据类型概述

JAVA 是一个 **`强类型语言`**，对于每一个数据都定义了明确的数据类型，并在内存中分配了不同大小的空间

- 初始化定义：初始化 = 申明 + 赋值
- 初始化意义：向计算机申请开辟一段空间，空间名是 arr，存储的类型是 int 数组
- 初始化写法

  - int a,b,c,d=10,e,f;
  - int a,b,c=10： a、b都未初始化，c=10

Java 数据类型主要分为 **`基本数据类型`**、**`引用数据类型`**

Java 中传的是数值还是地址：

- 基本数据类型传递的是数值，引用数据类型传递的是地址，数组传递的是地址（String 类型有些特殊，类似基本数据类型）
- 即使是地址也是值，java 传递的都是值（JAVA 之父高斯林说）

## 字符型

**`char`** `占 2 个字节`，`0 ~ 65535`

- char 描述的其实是：编码表中 int 值和字符之间的关系
- char 可以存储中文：Java 采用 UNICODE 编码，一个 char 占 2 个字节，中文也占 2 个字节

**`Character`**

- Character.MIN_VALUE 返回的是 char 类型
- Character.MIN_VALUE + 0 = '\u0000' + 0 = 0
- Character.MAX_VALUE + 0 = '\uFFFF' + 0 = 65535
- `\u 表示 unicode 编码`：每个数字表示的是 `4 位十六进制`

输出形式 

- 'a' + 0 输出 int 类型
- 'a' + "" 输出 String 类型
- 'a' + 'b' 输出的是 105（97+98）
- (int) 'a' 输出 int 类型，97
- char a = 97： 输出'a'

```java
// 当 ch 表示字符的时候，表示字符 a
// 当 ch 表示数字的时候，表示数字 97
char ch = 'a';					

System.out.println('a'+1+"hello");        // 输出98hello
System.out.println("hello"+'a'+1);        // 输出helloa1
```

### ASCII 表

char 在 ASCII 表中与特定的编码相对应

- 0：编码 48
- a：编码 97
- A：编码 65

char 和 int 的转化

- char 转 int
  - 如果 char 对应 ASCII 码表的值是数字（`减 48`）：int a = c-48
  - 如果 char 对应 ASCII 码表的值不是数字（直接转）：int a = c（输出的是 ASCII 码表中对应的数字）
- int 转 char（`加 48`）：char c = (char)(a+48)

char 的运算：char 会转成 ASCII 码表中的 `int 值` 再进行计算

String 和 char 的拼接：`直接拼接`（char 不会转化为 int）

## 整型

**`byte`**：占 1 个字节，-128 ~ 127

**`short`**：占 2 个字节，-2^15 ~ 2^15-1. 	  0-65535

**`int`**：占 4 个字节，-2^31 ~ 2^31-1           `整型默认类型`

**`long`**：占 8 个字节，-2^63 ~ 2^63-1        long a = 88888888L，需要加一个 `L`，表示是一个 long 类型

超出范围，输出 0

符号位：0 正数，1 负数

- 0 对应 0000 0000，而 1000 0000 则对应 -128，0111 1111 对应 127

<br/>

### 隐式转换

byte、char、short - int - long - float -double

**`隐式转换（类型提升）`**：小类型与大类型运算，小类型隐式转化为大类型

- 比 int 小的类型，会 `隐式转换为 int 类型`（short + int = int）
- 比 int 大的类型，`保持原样、不会进行转换`（int + long  = long）

**`强制转换`**：小类型与大类型运算，将运算结果强制转化为小类型，强制运算符也是用 `补码` 进行运算

- 如果运算结果，超出了范围，那么我们需要利用结果的补码进行反推

```java
// 正常计算
byte a = 3 ;
int b = 4 ;
a = a + b ;							// 隐式转化：byte 自动转化为 int	
b = (byte)(a + b) ;     // 强制转化：砍掉前3个8位 00000000 00000000 00000000 00000111			

// 超范围
byte a = 4 ;            // 源码、反码、补码：0000 0100
int b = 126 ;           // 源码、反码、补码：0000 0000 0111 1110
a = (byte)(a + b) ;     // -126：砍掉前3个8位，补码 1000 0010，反码 1000 0001，源码 1111 1110
```

### IEEE 754 表示法

**为什么会出现误差**

浮点数在计算机中存储符合 `IEEE 754 浮点数计算标准`

浮点数由 `符号位 S`、`阶码部分 E`、`尾数部分 M` 三个维度组成

1. **`符号位 S`**：0正，1负

1. **`阶码部分 / 指数部分 E`：决定了浮点数的主要取值范围**

   Float：8 位，范围 -127～128，<font color=green>**2<sup>E-127</sup>**（E 是指数部分的 "十进制" 值）</font>

   Double：11 位，范围 -1023～1024

   > **指数部分如何计算？**
   >
   > 以单精度浮点数 float 为例：底数为 2（8 位取值范围 0～255），偏移值 127，所以范围是 -127～128

1. **`尾数部分 M`：决定了浮点数的主要精度**（其实是由 指数部分和尾数部分 共同决定的）

   Float：23 位，2^23=8388608，精度是 `7 位`，<font color=green>**1.M**（M 直接用尾数部分的 "二进制值" 表示）</font>

   Double：52 位，2^52=4503599627370496，最高精度是 `16 位`

   > **尾数部分如何计算？**
   >
   > 以单精度浮点数 float 为例：1.M（M 直接用二进制数据套进去）

1. **`最终的计算公式`**：<font color=green>**(-1)<sup>S</sup> \* 10<sup>E 部分的十进制值</sup> \* (1.M 部分的二进制值)**，然后再转化为对应的十进制</font>

   <font color=green>整数部分取十进制，小数部分依次乘以 1/2、1/4、1/8</font>

   > **最终公式如何计算？**
   >
   > 例如 3.14159 的二进制是 0 10000000 10010010000111111010000
   >
   > 1. 符号位 0
   >
   > 2. 指数部分 10000000：对应十进制 128，计算偏移 128-127=1
   >
   > 3. 尾数部分 10010010000111111010000：1.M 前面+1 = 1.10010010000111111010000
   >
   > 4. 计算公式：
   >
   >    1.10010010000111111010000 * 10<sup>1</sup> = 11.0010010000111111010000
   >
   >    整数部分是 11=3
   >
   >    小数部分是 0010010000111111010000 = 1/8 + 1/64 + 1/2048 + 1/4096 + 1/4096\*2 + 1/4096\*4 + 1/4096\*8 + 1/4096\*16 + 1/4096\*64 = 0.1415901184
   >
   >    最终 = 3.1415901184

所以虽然 float 只占 4 个字节（32位），但是 `表示的范围要比 long 大`（存在阶码部分）

```java
public static void main(String[] args) {

  //构造对象
  BigDecimal bd1 = new BigDecimal("5.2");
  BigDecimal bd2 = new BigDecimal("1.3");

  //计算加减乘除运算并打印
  System.out.println(bd1.add(bd2)); 			// 加：6.5
  System.out.println(bd1.subtract(bd2)); 	// 减：3.9
  System.out.println(bd1.multiply(bd2)); 	// 乘：6.76
  System.out.println(bd1.divide(bd2)); 		// 除：4

  System.out.println("-------------------------------");
  //加法运算的区别
  System.out.println(0.1 + 0.2); //0.30000000000000004  有误差
  BigDecimal bd3 = new BigDecimal("0.1");
  BigDecimal bd4 = new BigDecimal("0.2");
  System.out.println(bd3.add(bd4));//0.3

  System.out.println("-------------------------------");
  //当进行除法运算时，有可能会遇到除不尽的情况
  BigDecimal bd5 = new BigDecimal("0.1");
  BigDecimal bd6 = new BigDecimal("0.3");
  System.out.println(bd5.divide(bd6));// 发生算数异常
  //进行四舍五入的手法处理
  System.out.println(bd5.divide(bd6, BigDecimal.ROUND_HALF_UP)); //0.3
}
```

**BigDecimal**

减法运算：

- divide 在除不尽的时候会报错（java.lang.ArithmeticException: Non-terminating decimal expansion; no exact representable decimal result）

```java

// 舍入模式
ROUND_CEILING        // 向正无穷方向舍入

ROUND_DOWN           // 向零方向舍入
ROUND_HALF_UP        // 向（距离）最近的一边舍入，除非两边（的距离）是相等,如果是这样，向上舍入, 1.55保留一位小数结果为1.6【四舍五入】

ROUND_UNNECESSARY    // 计算结果是精确的，不需要舍入模式
```

## 枚举

**`枚举`**：将变量一一列出，变量的值仅限于列举出来的值的范围（常量）

- 慎用枚举类型：在 Android 中，枚举占用的空间，**`比 static 常量占用的空间大 2 倍以上`**
- 输出：System.out.println(Week.MON) ，输出 MON
- 定义：直接定义枚举项 Week.MON，报错（因为它是一个 `常量`，就像单独写了一个 8，需要用一个变量来接受 ）

**`枚举类（类）：枚举的本质是一个类`**

- 每个枚举项都是一个 `实例对象（常量）`，本质是一个 `static final` 修饰的实例对象
- 枚举类：有多个实例的类
- 单例类：只有一个实例的类

**`枚举项（常量）：枚举项可以看作一个特殊的常量`**

- 静态常量 static final：`不被 GC（垃圾回收机制）管理`，有可能造成内存泄漏

- 枚举常量：`枚举更加有约束性`

<br/>

**`枚举类`** 是一个 `类`，**`Enum`** 的子类

- 枚举类的第一行上必须是枚举项，最后一个枚举项后的分号是可以省略的

  但是如果枚举类有其他的东西，这个分号就不能省略。建议不要省略

- 构造方法：枚举类可以有构造器，但 `必须是 private 的`，并且 `构造方法只会走一次`

- 抽象方法：枚举类也可以有抽象方法，但是 `枚举项必须重写该方法`

**`枚举项`** 是一个 `实例/常量`，相当于枚举类的一个实例对象

```java
// 空参构造
public enum Week {
    MON,TUE,WED;                // MON、TUE、WED都是枚举类型，它们都是 Week 的子类
}

// 有参构造 private
public enum Week {
    MON("星期一"),TUE("星期二"),WED("星期三");
    
    private String name;
    private Week(String name){

    public String getName(){
        return name;
    }
    public void setName(String name){
        this.name = name;
    }
}

// 有抽象方法
public enum Week {

        public void show(){
            System.out.println("星期一");
        }
    },
    TUE("星期二"){
        public void show(){
            System.out.println("星期二");
        }
    },
    WED("星期三"){
        public void show(){
            System.out.println("星期三");
        }
    };
    
    private String name;
    private Week(String name){
        this.name = name;
    }
    public String getName(){
        return name;
    }
    public void setName(String name){
        this.name = name;
    }
    public abstract void show();
}
```

### 单例和设计模式

**单例**

枚举项可以看作是一个 "**`在类加载的时候（类级别）、由 JVM 自动创建（线程安全）、并且保证全局唯一的单例对象（单例）`**"

为什么可以使用枚举创建一个单例

1. `枚举的构造方法只会走一次，并且是私有化的`

   外部无法通过 new 关键字创建实例，确保了实例数量

2. `自然的单例属性`

   枚举项的实例是在加载枚举类的时候由 `JVM` 自动创建并初始化的，这意味着枚举项的每个实例都是一个单例

枚举创建单例的好处：**它是一个非常简洁且安全的单例实现方式**

1. `天然的线程安全`

   由于 JVM 加载枚举类的过程是线程安全的，因此枚举项的实例化过程也是线程安全的

2. `避免反射攻击`

   通过反射调用枚举项的私有构造方法创建实例，将会抛出异常，阻止了通过反射绕过单例限制的行为

3. `避免反序列化攻击`

   枚举类型在序列化和反序列化的过程中，不会创建新的实例对象，而是通过 `readRsolve()` 方法返回已经存在的枚举实例，从而维持单例特性

4. `简洁性`

   无需用 static 修饰

   无需双重检查加锁

```java
public class Singleton {

  private Singleton(){}

  public Singleton getInstance() {
    return SingletonEnum.SEED.singleton;

    SEED;		// 我们称之为“种子选手”

    private Singleton singleton;

    SingletonEnum() {
      singleton = new Singleton();
    }
  }
}
```

## 数组

数组：在系统中开辟一组连续的内存空间，是存储同一数据类型多个元素的集合（Object[] 除外，它可以存储任意数据类型）

- 数组的长度不可变
- 数组不是基本数据类型，而是引用数据类型

**`动态初始化`**：定义数组长度，由系统分配初始值

- int[] arr = new int[5];

**`静态初始化`**：定义初始值，由系统分配长度

- int[] arr = new int[]{11,22,33,44,55} 
- int[] arr = {11,22,33,44,55}

**`空数组`**

- new int[0]，错误写法 new int[]

**`多维数组`**

- 八维数组：表示每个八维数组都是一个七维数组

- int arr\[][] = new int\[3][2]：表示有 3 个一维数组，每个一维数组含有 2 个元素

- int\[][] arr = new int\[3][];    arr[1]值是一个引用数据，默认初始值是 Null

**`数组的初始化值`**

- 整型 byte / short / int / long：0

- 浮点型 float / double：0.0

- 布尔值 boolean：false

- 字符串 String：null

- 字符型 char：'\u0000'

**`数组的输出形式`**

- System.out.prinln(arr)：输出 [I@19bb25a
  - [ 表示数组，有几个 [ 就表示是几维数组
  - I 表示int类型
  - 19bb25a 表示内存地址，十六进制的内存地址
- 数组默认输出的是地址值，char[] 数组比较特殊，输出的是值
- Arrays.toString(arr)：输出数组

数组的长度在 Java 中用一个 int 类型表示，因此最大长度理论上是 `2^31-1`，但是实际上会受 JVM 可用内存的限制

<br/>

## 字符串

String 的最大长度、最大大小分为编译期、运行期

- `编译期（字母值常量）`：最大长度 2^16-1=65535，最大大小也是 65535
- `运行期（字符串对象）`：最大长度 2^32-1，最大大小看 JVM 允许的最大内存

如果我们直接用 `字面值常量` 定义一个 String，那么它是存储在 `常量池中的 CONSTANT_String_info`，它允许的最大长度是 u2 两个字节 2^16-1=65535

但是如果我们用 `new String()` 的形式定义一个 String，那么它在 String 内部是以 `char[] 字符数组` 形式存在的，它允许的最大长度就是数组长度，数组的理论长度是 `2^31-1`，但是受 Java 虚拟机内存限制，它的最大长度可能无法到达这个理论上的最大值

# 常量

**`常量`**：一旦赋值/初始化，值便不可更改，否则编译器会报错

- **初始化**：常量必须在 <u>"声明时"、"构造函数 final"、"静态代码块 static final"</u> 中进行初始化

  ```java
  public class Example {
    public final int a = 10;		// 声明时初始化
    public final String b;
    public static final File f;
    
    public Example() {
      b = "小猫";			      // 构造函数中初始化
    }
    
    static {
      f = new File();			     // 静态代码块中初始化
    }
  }
  ```

- **修饰符**：

  `final` 实例常量

  `static final` 类常量

- **类型**：可以是任意 <u>基本数据类型（int、double、char 等）或引用类型（如 String、enum）</u>

  `基本数据类型 + String`：是一个真正意义上的常量

  `引用数据类型`

  `枚举类型 enum`：是一种更加结构化的方式（避免非法值），用来定义一组相关的常量（<u>枚举常量默认是 public static final 修饰</u>）

  ```JAVA
  public enum Status {
      SUCCESS, FAILURE, PENDING;
  }
  ```

<BR/>

**`编译时常量`**：在编译时就能确定的常量（声明时直接初始化）

- 常量在编译时直接 `内联` 到代码中，直接使用值本身、而非引用常量
- 如果编译时常量发生变化，需要重新编译，否则可能使用旧值
- 必须是 `基本数据类型 + String` 类型

**`运行时常量`**：在运行时确定的常量（在构造函数或者静态代码块中初始化）

- 使用引用常量，适合动态环境
- 可以是任意类型

<br/>

**`字面值常量`**：基本数据类型的常量（字符常量、字符串常量、整数常量、小数常量、布尔常量、空常量）

**`自定义常量`**：final 修饰

Kotlin 中的常量

  `const val` 编译时常量：const 专门用来修饰编译时常量

  `val` 运行时常量：仅仅表示它是不可变更的

- 必须定义在 `顶级作用域、object、companion object` 中，而不能定义在类或者函数的实例作用域中
- 必须是 `基本数据类型 + String`

## 内存

**编译时常量**

- 存储在 `方法区的常量池` 中（类信息、静态变量、常量池）
- 在 JDK 7 之前，常量池位于方法区中；在 JDK 7 及之后，常量池移到了堆中

**运行时常量**

- static final：存储在 `方法区的静态变量` 区域中

  <u>引用存储在方法区的静态变量区域中，实际 String 对象存储在堆中，字符串可能进一步存储在字符串常量池中</u>

  ```java
  public class RuntimeConstants {
      public static final String START_TIME;
      static {
          START_TIME = new SimpleDateFormat("yyyy-MM-dd").format(new Date());
      }
  }
  ```

- final：存储在 `堆` 中

  每个对象实例都有自己的常量副本

**字符串常量池**

- 不管是编译时常量，还是运行时常量，如果值是 String 字面量，JVM 会将其存储在 `字符串常量池` 中

  ```java
  public class Test {
      public static final String NAME = "MyApp";		// 编译时常量
      public final String AGE;					 // 运行时常量
      public Test() {
          AGE = "10";
      }
  }
  ```

- 动态字符串：如果 String 值是在运行时生成（new String("MyApp")），则存储在 `堆` 中，不在 "字符串常量池" 中

  除非显示调用 `intern()`

**枚举常量 enum**

- 每个枚举常量都是类的静态单例对象，因此它们的引用都存储在 `方法区的静态变量区域`，实例存储在 `堆` 中

## 常量优化机制

常量相加：Java 编译器有 **`常量优化机制`**，在编译过程中会自动判断类型、以及取值范围

常量优化机制 1：**`自动替换为对应的值`**

- 常量如果在定义的时候就进行了初始化，那么所有用到的地方都被替换成了常量值（即 return name，被替换成了 return "xx"）（<u>反射失效</u>）
- 常量如果在定义的时候没有初始化，那么所有用到的地方还是常量对应的变量

常量优化机制 2：**`String 常量的拼接`**

- 如果是 2 个 String 变量相加，则会在堆中开辟新空间
- 如果是 2 个 String 常量相加，则会在常量池中开辟新空间（常量池中如果没有，则创建一个；如果有，则使用原来的常量）

常量优化机制 3：**`byte 常量运算`**

- byte 在计算过程中，会自动转为 int 类型
- 如果是 2 个 byte 变量相加，必须进行强转（否则报错）
- 如果是 2 个 byte 常量相加，可以直接进行转换（会自动判断是否超过了 byte 的取值范围）

```java
// byte 变量相加
byte a = 3;
byte b = 4;
byte c = a + b;								// 正确的写法：byte c = (byte)(a + b);
System.out.printIn(c);
// 会报错：要求强制转化为int类型
// 1. 运算过程中a和b会自动转为int类型，比int小的会自动转为int，比int大的不转化
// 2. 变量的存储值是变化的，在编译的时候无法判断其中的值，有可能超过byte的取值范围

// 常量相加
byte c = 3 + 4;
// 不会报错
// JAVA编译器有常量优化机制，在编译的过程中就会判断，是否超过byte的取值范围
```

# 数据比较

参考：《[Java 中的 ==, equals 与 hashCode 的区别与联系](http://blog.csdn.net/justloveyou_/article/details/52464440)》

<br/>

**`==`**：基本数据类型比较的是值、引用数据类型比较的是内存地址

**`equals()`**：比较的是内容

- Object 默认比较的是 `地址（==）`
- String 对其进行了重写，比较的是 `内容`

**`hashCode()`**：是对 equals 方法的扩充，有可能发生哈希碰撞

- Object 使用 native 方法 `对地址值取散列值`
- String 对其进行了重写，是 `对字符串内容取散列值`

hashCode 用来确定哈希表的索引位置，是对 equals() 对补充

- 在哈希表中，`先用 hashCode()` 确定元素下标
- 只有存在哈希碰撞的时候，`再调用 equals()` 方法进行比较

<br/>

## == 关系操作符

对于 8 种 **`基本数据类型`**，Java 存储的是 `值`，因此 == 比较的是值本身

对于 **`引用数据类型`**，Java存储的是 `内存中的地址`，因此 == 比较的是内存中的地址

<br/>

## equals()

equals 比较的是2个对象的内容（只能适用于 **`引用数据类型`**）

equals 重写步骤

1. 比较地址值

2. 比较类型

3. 比较内容

equals 重写原则

- 对称性
- 自反性
- 类推性
- 一致性
- 在任何情况下，x.equals(null)、x.equals(不同类型) 返回的都是 false

<br/>

**Object**

**`Object`** 是所有类的父类，它的 equals 方法，比较的是地址值（==），没有什么意义，一般都需要我们对其进行重写 

```java
public boolean equals(Object obj) {
    return (this == obj);
}
```

<br/>

**String**

**`String`** 中，重写了 equals 方法

1. 比较地址值，是否相同

2. 比较类型，是否相同

3. 比较字符个数，是否相同

4. 用 == 号逐个比较字符，是否相同

```java
public boolean equals(Object anObject) {
    if (this == anObject) {                          // 1. 比较地址值
        return true;
    }
    if (anObject instanceof String) {                // 2. 是否是同一个类型
        String anotherString = (String) anObject;
        int n = count;
        if (n == anotherString.count) {             // 3. 判断字符个数，是否相等
            int i = 0;
            while (n-- != 0) {                      // 4. 用 == 逐个比较对应位置的字符
                if (charAt(i) != anotherString.charAt(i))
                    return false;
                i++;
            }
            return true;
        }
    }
    return false;
}
```

## hashcode()

**`哈希值（散列值）`** 的概念：将任意长度的输入（`预映射，pre-image`），通过散列散算法，转换成固定长度的输出（`散列值，int`）

- 这是一种压缩映射，即将大范围的数据映射为小范围的数据
- 不同的输入，可能会有相同的输出，所以我们不能用散列值来唯一确定一个对象

哈希值的作用：通常应用在需要哈希算法的数据结构中（**`哈希表，也叫散列表`**）确定索引位置，比如 HashSet、HashMap、HashTable 等

- 在哈希表中，我们通过哈希值，判断元素在哈希表中的索引值；
- 确定完索引值后，在逐一比较当前链表中的元素是否相等（先比较哈希值，如果相等，再调用 equals 方法进行比较）；
- 如果相等，替换当前元素；如果没有，放在当前链表的表头

hashCode() 是对 equals() 方法的补充

- <u>equals() 的比较比较麻烦，而 hashcode() 只需要比较一个 int 值即可</u>

<br/>

**Object**

**`Object`** 的 hashcode：将不同对象的内存地址和值，通过 native 方法，转换成一个整数 int

- 通常不同对象的哈希值不同，同一个对象改变内容后，哈希值理论上也应该不同（可能相同）
- null 的哈希值是 0

<br/>

**String**

**`String`** 的 hashcode：

- 理论值：s[0]\*31^(n-1) + s[1]*31^(n-2) + ... + s[n-1]
- 可以看到对象的哈希值，不一定是内存地址值
- 为什么是 31：2^5-1，`降低哈希值碰撞的概率`

```java
public int hashCode() {
    int h = hash;
    if (h == 0 && count > 0) {
        for (int i = 0; i < count; i++) {
            h = 31 * h + charAt(i);
        }
        hash = h;
    }
    return h;
}
```

<br/>

**equals 和 hashcode 的区别**

它们都是 Object 特有的方法

Object 的 equals 方法，比较的是 `地址值（==）`

Object 的 hashCode 方法，比较的是 `地址值 + 内容`，但是有一定的几率发生哈希碰撞

- 如果 x.equals(y) 为 true，那么 2 者的 hashcode 一定相等
- 如果 x.equals(y) 为 false，那么 2 者的 hashcode 可能相等、也可能不等
- 如果 2 者的 hashcode 相等，那么 x.equals(y) 可能为 true、也可能为 false
- 如果 2 者的 hashcode 不等，那么 x.equals(y) 一定为 false
